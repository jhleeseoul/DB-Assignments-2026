과제명: Project 1-1 SQL Parser (DB_2022-18758)

1. Python 버전 및 사용 라이브러리
- Python 버전: `3.12.3` (venv 기준)
- 외부 라이브러리: `lark==1.3.1`
- 표준 라이브러리: `pathlib`, `subprocess`, `re`, `sys`

2. 핵심 모듈과 알고리즘 설명
- `grammar.lark`: 스켈레톤 대비 핵심 차이로 시작 규칙을 `query_list | EXIT ";"`에서 `start : command`로 바꿨고, `command`에서 `query`와 `exit_query`를 분리했다. 스켈레톤에 없는 DDL/DML/관리구문을 추가해 `DROP/EXPLAIN/DESCRIBE/DESC/SHOW TABLES/RENAME/TRUNCATE/INSERT/DELETE/UPDATE`를 `query` 집합에 넣었고, `INSERT`, `DELETE`, `UPDATE`도 개별 규칙으로 구현해 과제의 2.1/2.2 요구 SQL 전부를 커버했다. 비교 연산자는 `COMP_OP` 합성 규칙을 제거하고 `comparison_op`로 직접 토큰 조합 방식으로 바꿔 충돌을 회피했으며, `LIMIT`, `OFFSET`, `where` Boolean식(`and/or`, 괄호, null predicate), `SELECT` 확장 규칙을 추가했다. 식별자 충돌을 피하기 위해 키워드 토큰과 `IDENTIFIER`/`%ignore WS` 정책은 스켈레톤과 같은 방식으로 유지해 공백·개행을 안전하게 무시했다.
- `run.py`: `build_parser()`에서 `grammar.lark`를 읽어 `Lark(..., start="command", lexer="basic")`로 파서를 만들고, 입력 라인을 누적해 `extract_statements()`로 세미콜론 기반 분리를 수행한다. 따옴표 내부 `;`는 분리하지 않고, escape 정보를 추적해 문자열 내 오분리를 방지한다. `parse_statement()`의 트리는 `CommandTransformer`로 축약되어 실제 쿼리 라벨로 변환되며, `command`, `query`는 `items[0]`로 상위 규칙을 제거해 한 단계 결과만 남기고 `exit_query`는 `"__EXIT__"` 시그널로 즉시 종료를 처리한다.
- `validate.py`: 파서 단위 테스트와 실행 단위 테스트를 통합해 문법 정상/비정상 케이스, query sequence, 멀티라인 입력, 문자열 내 `;`, `exit` 동작, limit-offset 순서, 예약어 제한을 자동으로 검증한다.

3. 구현한 내용
- `grammar_skeleton.lark`에서 비어 있던 영역(`DROP`, `INSERT`, `DELETE`, `UPDATE` 등)을 과제 필수 문법으로 모두 구현했다.
- 구현한 SQL 집합은 기본으로 `SELECT`, `CREATE TABLE`을 두고, 추가로 `INSERT`, `DELETE`, `UPDATE`, `DROP`, `EXPLAIN`, `DESCRIBE`, `DESC`, `SHOW TABLES`, `RENAME`, `TRUNCATE`, `exit`를 완성했다.
- `command`/`query` 분기 전략으로 한 번의 입력에서 여러 쿼리(세미콜론 구분)를 처리하고, `exit` 토큰은 즉시 종료 분기로 분리되도록 구성했다.
- `where` 절에서 비교·논리식을 `boolean_expr` 기반으로 통합 설계해 `SELECT/DELETE/UPDATE` 모두에서 공통 재사용했다.
- 문자열 내 세미콜론을 분리 대상에서 제외하기 위해 `extract_statements()`에서 인용부호 상태 추적과 escape 처리를 적용했다.
- 스켈레톤 대비 구현한 핵심 알고리즘 차이: 토큰 단계와 규칙 단계를 명확히 나눠, `CommandTransformer`가 parse tree의 rule 메서드(`select_query`, `insert_query` 등)를 매핑해 반환 문자열 라벨로 축약한다.
- 현재 `validate.py`로 문법 케이스(정상/오류), `run.py` 출력 형식, query sequence, 멀티라인 입력, limit-offset 순서 제약, 예약어 사용 제한을 통합 검증한다.

4. 프로젝트를 하며 느낀 점 및 기타 사항
- 파서 작업은 테스트가 핵심이다. 작은 문법 변경이 특정 연산자(`=`) 하나에서만 실패를 만들 수 있어, 수동 점검보다 자동 검증이 효과적이다.
- Transformer는 “트리 노드→매칭 규칙 메서드 호출→결과 축약” 흐름이라 디버깅 학습에 좋았다.
- `%start` 지시자보다 `start : command` 방식이 이 환경에서 안정적이라 실제 실행 호환성의 중요성을 다시 느꼈다.
- 과제 범위 밖 확장(예: 더 많은 형식 오류 메시지, 에러 위치 표시)은 현재 미구현이지만, 문법 기반 파서 파이프라인은 그쪽으로 확장 여지가 충분하다.

5. 작업 과정에서 사용한 AI 도구
- 사용 도구: ChatGPT 기반 Codex
- 사용 목적: 문법(rule) 구성 브레인스토밍, Lark Transformer/parse tree 개념 정리, 파싱 실패 원인 추적 및 테스트 시나리오 보강, 보고서·검증 코드 문장 정리였다.
- 반영 방식: 제안된 아이디어를 그대로 복사하지 않고 README 요구사항(입력 종료 규칙, 출력 형식, query sequence, 예약어 처리)에 맞춰 선택 적용했다. 실패한 케이스는 `validate.py`로 재현 후 수정해 통과 여부를 확인했다.
